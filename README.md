# m6media — конвертер видео для Haval M6 (2023): AVI/XviD, AC3, USB

[![tests](https://github.com/qomyagin/m6media/actions/workflows/ci.yml/badge.svg)](https://github.com/qomyagin/m6media/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)
[![Python 3.9+](https://img.shields.io/badge/python-3.9%2B-blue.svg)](pyproject.toml)

> **Haval M6 не видит фильм на флешке, не воспроизводит AVI/XviD или MKV
> с AC3?** Обычно дело не в exFAT и не в имени файла, а в кодеке: M6
> заявляет AVI как контейнер, но не декодирует MPEG-4 Part 2 (XviD/DivX).
> `m6media` находит такие файлы, конвертирует **только их** в H.264/AAC
> MP4 и не трогает то, что уже работает.

Скрипт готовит видео, музыку и фото для мультимедиа Haval M6 (M6 Plus,
российское издание 2023–2026) и объясняет, почему конкретный файл не
показывается.

Проверено на реальной **exFAT-флешке** и реальных файлах: AVI/XviD не
отображались, MKV/H.264 работали. Подробный разбор — в разделе
«Почему Haval M6 не воспроизводит AVI/XviD».

Полезные ссылки: [FAQ](FAQ.md) · [матрица совместимости](docs/COMPATIBILITY.md) · [English](README.en.md)

## Частые проблемы

| Симптом | Что проверить |
|---|---|
| Haval M6 не видит AVI | XviD/DivX/MPEG-4 Part 2 → перекодировать в H.264 |
| Видео есть, звука нет | AC3/E-AC3/DTS → AAC stereo |
| Файл > 4 ГБ не копируется | FAT32 → exFAT или `--fat32 split` |
| Флешка не видна | FAT32/exFAT, не NTFS; проверить разметку |
| Часть файлов играет, часть нет | разные кодеки; запустить `--diagnose` |

Полный разбор: [FAQ.md](FAQ.md) и [docs/COMPATIBILITY.md](docs/COMPATIBILITY.md).

## Что делает скрипт

1. Читает файлы (папки рекурсивно) и определяет контейнер, кодеки,
   разрешение, fps, звук — через `ffprobe`.
2. Решает, можно ли файл просто перепаковать/скопировать или нужно
   перекодировать. Если файл уже совместим с M6, по умолчанию он
   **пропускается** и не дублируется в выходной папке.
3. Приводит **несовместимое** видео к целевому формату:
   * контейнер **MP4** (`+faststart`, `mp42`) или **MKV** по
     `--container mkv` (если конкретная прошивка капризничает с MP4);
   * видео **H.264 Main@4.0**, 8 бит, 4:2:0 (`yuv420p`), до 1920×1080,
     до 30 кадров/с, CRF 21 с ограничением битрейта;
   * звук **AAC-LC**, 48 кГц, стерео, 192 кбит/с.
4. Приводит несовместимую музыку к **MP3** (CBR 256 кбит/с, 44,1 кГц,
   стерео, ID3v2.3 + ID3v1) либо к AAC/M4A по выбору. Совместимые
   MP3/WMA/AAC/FLAC/WAV/OGG не трогает.
5. Приводит несовместимые фото к **JPEG** (sips на macOS понимает
   HEIC/RAW; ffmpeg — запасной вариант). Совместимые JPG/PNG/BMP
   не трогает.
6. Раскладывает результат по папкам `Video/`, `Music/`, `Photo/`.
7. При необходимости **разбивает видео на части < 4 ГиБ** — это
   ограничение FAT32. На exFAT разбиение автоматически отключается.
8. Пишет отчёт `_m6media/manifest.json`, `manifest.csv`, `run.log`
   и умеет проверять готовую папку (`--check-only`).

Исходники скрипт **не изменяет и не удаляет**. Он только читает их и
пишет результат в указанную папку.

По умолчанию в выходную папку попадают **только те файлы, которые
реально нужно было исправить**. Совместимые файлы остаются на месте.
Если нужна полная копия/нормализация всего в целевой формат — добавьте
`--normalize`.

## Форматы, которые заявлены в инструкции

Инструкция Haval M6 Plus (российское издание 2023–2026), страница 116
по колонцифре ([скан](https://mcgrp.ru/files/viewer/1112377/117)):

| Тип | Форматы |
|---|---|
| Аудио | MP3, WMA, AAC, FLAC, WAV, OGG |
| Видео | WMV, MP4, MPEG, AVI, 3GP, MKV, MOV, ASF, VOB |
| Фото | JPG, PNG, BMP |
| USB | FAT16, FAT32 |

Важно: **список контейнеров ничего не говорит о кодеках**. Внутри AVI
может быть XviD/DivX (MPEG-4 Part 2), который M6 не декодирует,
хотя сам AVI формально «поддерживается». Поэтому скрипт смотрит не на
расширение, а на потоки.

Целевой набор `MP4 / H.264 / AAC` выбран как самый совместимый.
Если конкретная прошивка лучше читает MKV (проверенные рабочие файлы — MKV),
добавьте `--container mkv`: кодек и звук останутся теми же, изменится
только обёртка.

* H.264 — аппаратный декодер M6 его понимает (проверенные рабочие файлы — H.264);
* AAC-LC — заявлен в инструкции и не требует лицензионных AC3/DTS;
* MP4 — контейнер из списка, с `faststart` для быстрого старта;
* 8-бит 4:2:0 — не HDR/10-бит, которые автомобильные плееры часто не читают.

## Почему Haval M6 не воспроизводит AVI/XviD

Пример реальных параметров потоков (имена обезличены):

| Файл | Контейнер | Видео | Звук | Результат |
|---|---|---|---|---|
| `movie-xvid-1.avi` | AVI | MPEG-4 ASP (XviD), 704×384, 23,976 | AC3 5.1 | не показывался |
| `movie-xvid-2.avi` | AVI | MPEG-4 ASP (XviD), 720×400, 23,976 | AC3 5.1 | не показывался |
| `movie-xvid-3.avi` | AVI | MPEG-4 ASP (XviD), 720×384, 24 | AC3 5.1 | не показывался |
| `movie-xvid-4.avi` | AVI | MPEG-4 ASP (XviD), 704×352, 24 | AC3 5.1 | не показывался |
| `movie-h264-1.mkv` | MKV | H.264 High@4.1, 1104×462, 24 | AC3 5.1 | работал |
| `movie-h264-2.mkv` | MKV | H.264 High@4.1, 1152×480, 24 | AC3 5.1 | работал |
| `movie-h264-3.mkv` | MKV | H.264 High@4.1, 1152×480, 23,976 | AC3 5.1 | работал |

**Вывод:** общий признак неработающих файлов — **AVI + MPEG-4 Part 2
(XviD/DivX)**, а рабочих — **MKV + H.264**. Инструкция заявляет AVI как
контейнер, но кодека XviD/DivX в списке поддерживаемых нет; возможно,
дело в кодеке, возможно — в связке AVI+XviD. В любом случае целевой
H.264 в MP4/MKV убирает оба отличия. Имена, размер, кириллица и
exFAT тут ни при чём: рабочие файлы тоже могут быть с кириллицей, лежать
на той же exFAT-флешке и весить столько же. AC3 5.1 в MKV M6 тоже
читает, но для MP4 надёжнее AAC.

Скрипт для этих файлов делает так:

* XviD/AVI → перекодирует видео в H.264 Main@4.0, звук AC3 → AAC;
* H.264/MKV + AC3 → копирует видео без потерь, меняет контейнер на MP4,
  звук AC3 → AAC (быстро, без повторного сжатия картинки);
* разрешение не увеличивает: 704×384 останется 704×384.

### Почему в отчёте бывает действие `copy-video`?

Если запустить с `--normalize`, скрипт обрабатывает и совместимые файлы.
Для H.264/MKV+AC3 он делает не перекодирование картинки, а `copy-video`:

* видео H.264 копируется бит-в-бит (`-c:v copy`) — качество не меняется;
* AC3 5.1 → AAC stereo;
* MKV → MP4.

В логе это видно по строке `-c:v copy`. По умолчанию такие файлы
**пропускаются**: скрипт обрабатывает только то, где нужно перекодировать
картинку (XviD/DivX, H.264 вне профиля, HDR и т. п.).

```bash
./m6media.py /Volumes/USB
```

## Установка

Скрипт лежит в этой папке; сделайте его исполняемым:

```bash
chmod +x m6media.py
```

Нужны Python 3.9+ и ffmpeg с `libx264`, `aac`, `libmp3lame`.

### macOS

```bash
brew install ffmpeg
```

Проверка:

```bash
ffmpeg -version
python3 --version
```

Для `--burn-subs` (вжигание субтитров) и `--tonemap` (HDR→SDR) нужна
сборка с `libass`/`zscale`. В обычной формуле Homebrew их нет; можно
поставить `ffmpeg-full` (keg-only) и указать путь:

```bash
brew install ffmpeg-full
./m6media.py … --ffmpeg /opt/homebrew/opt/ffmpeg-full/bin/ffmpeg \
                 --ffprobe /opt/homebrew/opt/ffmpeg-full/bin/ffprobe
```

### Linux

```bash
sudo apt install ffmpeg       # Debian/Ubuntu
sudo dnf install ffmpeg       # Fedora
```

### Windows

```powershell
winget install Gyan.FFmpeg
```

Скрипт сам ищет `ffmpeg` в `PATH`, `/opt/homebrew/bin`, `/usr/local/bin`,
`/usr/bin`. Можно указать явно: `--ffmpeg PATH`, `--ffprobe PATH`.

## Быстрый старт

### 1. Диагностика флешки (ничего не пишет)

```bash
python3 m6media.py /Volumes/USB --diagnose
```

Скрипт покажет по каждому файлу: контейнер, кодеки, разрешение, звук,
действие и причину. Это лучший способ понять, почему файл не виден.

### 2. Подготовить только проблемные файлы

```bash
python3 m6media.py /Volumes/USB
```

И всё. Папка `M6` создастся рядом с исходниками — на той же флешке.
По умолчанию скрипт:

* **пропускает совместимые файлы** — MKV/H.264, MP3/FLAC/WAV,
  JPG/PNG/BMP и т. п.;
* **пропускает служебные** `.srt`, `._*` и внешние `.ac3` рядом с фильмом;
* **обрабатывает только несовместимое** — например, AVI/XviD;
* сам определяет exFAT и не режет файлы по 4 ГиБ.

В `M6` появятся только исправленные несовместимые файлы. Совместимые
MKV останутся на месте и не будут продублированы.

Полезные необязательные добавки:

```bash
# быстрее (для 480p почти без потери качества)
... --x264-preset veryfast

# сразу проверить результат
... --check

# если нужно перенести/перепаковать ВСЁ, включая совместимое
... --normalize
```

Если нужен **единый** формат для всех файлов, `--normalize` перепакует
рабочие MKV в MP4/AAC с копированием видео (`copy-video`), без потери
качества картинки.

### Повторный запуск и `--force`

Если файл с таким именем уже есть в `M6`, скрипт его **не трогает**:
пишет в итоговом списке «файл уже существует…» и продолжает. Чтобы
перезаписать:

```bash
./m6media.py /Volumes/USB --force
```

`--force` перезаписывает только то, что скрипт и так бы обработал.
Совместимые файлы всё равно пропускаются; чтобы перезаписать и их —
`--normalize --force`.

Файловая система определится автоматически:

* **exFAT** → разбиение по 4 ГиБ отключается, каждый фильм одним файлом;
* **FAT16/FAT32** → включается режим `fit` (ужать битрейт под 4 ГиБ)
  или `split` (разбить на части).

### 3. Проверить готовое

```bash
python3 m6media.py /Volumes/USB/M6 --check-only
```

### 4. Локальная подготовка (потом скопировать на флешку)

```bash
python3 m6media.py ~/Movies -o ~/m6-ready --preset compat
```

Если целевая флешка — exFAT, а готовите локально:

```bash
python3 m6media.py ~/Movies -o ~/m6-ready --fat32 off
```

## Примеры

### Только несовместимые файлы

```bash
python3 m6media.py /Volumes/USB --only video
```

Скрипт сам пропустит совместимые. Если нужно перечислить файлы вручную,
передайте пути:

```bash
python3 m6media.py "/Volumes/USB/Movie 1.avi" "/Volumes/USB/Movie 2.avi"
```

### Перекодировать всё заново, даже совместимое

```bash
python3 m6media.py ~/Movies -o ~/m6-ready --mode encode --preset quality
```

### Сохранить оригинальные имена (кириллица, пробелы)

```bash
python3 m6media.py ~/Movies -o ~/m6-ready --keep-names
```

По умолчанию имена транслитерируются в ASCII, **без номеров**:
`Pinokkio_Gilermo_del_Toro_2022.mp4`. Это максимально безопасно для
старых головных устройств. Если хочется стабильный порядок — добавьте
`--number` и получите `001_Pinokkio...mp4`. M6 кириллицу в именах
показывает, поэтому `--keep-names` тоже рабочий вариант.

### Только музыка / только фото

```bash
python3 m6media.py ~/Music -o ~/m6-ready --only audio
python3 m6media.py ~/Photos -o ~/m6-ready --only image
```

Совместимые MP3/WMA/AAC/FLAC/WAV/OGG и JPG/PNG/BMP по умолчанию
не трогаются. Если нужно пережать музыку в MP3 или уменьшить фото —
добавьте `--normalize`.

### Проверить, что файл уже совместим

```bash
python3 m6media.py file.mkv --dry-run
```

## Ключевые параметры

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `-o, --output` | `M6` рядом с исходниками | папка результата |
| `--preset` | `compat` | `compat` / `quality` / `compact` |
| `--mode` | `auto` | `auto` — только несовместимое; `copy` — без перекодирования; `encode` — всё заново |
| `--container` | `mp4` | `mp4` или `mkv` (MKV — если MP4 не идёт на конкретной прошивке) |
| `--only` | `all` | `video` / `audio` / `image` |
| `--normalize` | — | обработать всё, включая уже совместимые файлы (по умолчанию совместимые пропускаются) |
| `--fat32` | `auto` | `fit` — ужать под 4 ГиБ; `split` — разбить; `off` — не ограничивать |
| `--max-file-size` | `3.8G` | лимит файла (FAT32 — меньше 4 ГиБ) |
| `--max-width/--max-height` | 1920/1080 | максимальный размер кадра |
| `--fps` | 30 | максимум кадров/с; `0` — не ограничивать |
| `--video-crf` | 21 | качество x264 (меньше — лучше/больше) |
| `--x264-preset` | `medium` | скорость x264: `veryfast` быстрее, `slow` качественнее |
| `--video-maxrate` | 8M | потолок битрейта видео |
| `--audio-format` | `mp3` | `mp3` / `aac` / `copy` |
| `--audio-bitrate` | 256k | битрейт музыки |
| `--photo-max` | 1920 | длинная сторона фото; `0` — не уменьшать |
| `--photo-quality` | 90 | качество JPEG |
| `--jobs` | авто (2 на 8 ядрах) | параллельных файлов; для USB лучше 1–2 |
| `--threads` | авто | потоков x264 на задачу (ядра / jobs) |
| `--dry-run` | — | показать план, ничего не писать |
| `--diagnose` | — | подробная диагностика (= dry-run + verbose) |
| `--force` | — | перезаписать готовые файлы |
| `--keep-names` | — | не транслитерировать имена (кириллица сохраняется) |
| `--number` | — | добавить номера `001_`, `002_` к именам |
| `--check` | — | проверить результат после обработки |
| `--check-only` | — | только проверить готовую папку |
| `--burn-subs` | — | вжечь внешние `.srt/.ass` (нужен libass) |
| `--tonemap` | — | HDR→SDR (нужен zscale) |
| `--usb` | — | выход на USB; проверить ФС и место |
| `--exclude` | — | исключить маску, можно несколько раз |
| `--verbose` | — | подробный журнал и прогресс |

Профили:

| Профиль | Размер | CRF | Потолок видео | Звук |
|---|---|---|---|---|
| `compat` | 1920×1080 | 21 | 8 Мбит/с | AAC 192k |
| `quality` | 1920×1080 | 19 | 12 Мбит/с | AAC 256k |
| `compact` | 1280×720 | 23 | 3 Мбит/с | AAC 128k |

## Как работает разбиение под FAT32

FAT32 не позволяет файл ≥ 4 ГиБ. Скрипт считает длительность и битрейт
и заранее выбирает один из вариантов:

* `fit` (по умолчанию для FAT) — снижает потолок битрейта так, чтобы
  один фильм уложился в `--max-file-size`. Если для этого пришлось бы
  опуститься ниже разумного минимума (2,2 Мбит/с для 1080p,
  1,2 Мбит/с для 720p), включается разбиение;
* `split` — сохраняет качество и режет видео на равные части
  `..._part01.mp4`, `..._part02.mp4`;
* `off` — не ограничивать (exFAT/NTFS/локальный диск).

После кодирования скрипт ещё раз проверяет фактический размер. Если
файл всё-таки превысил лимит, он автоматически перекодирует его с
большим числом частей.

Для exFAT-флешки разбиение не нужно: файлы могут быть больше 4 ГиБ.

```
M6/
├── Video/
│   ├── movie-xvid-1.mp4
│   ├── movie-xvid-2.mp4
│   └── ...
├── Music/                 # только если что-то конвертировалось
├── Photo/                 # только если что-то конвертировалось
└── _m6media/
    ├── manifest.json      # полный отчёт: источники, потоки, действия, ошибки
    ├── manifest.csv       # то же для Excel
    └── run.log            # журнал
```

Здесь только то, что реально конвертировалось. Совместимые файлы
остаются на исходном месте — в выходную папку они не копируются.
С `--normalize` в папке будет полный набор.

`_m6media` можно удалить перед вставкой флешки в машину, но отчёт удобен
для разбора.

## Почему именно H.264 Main@4.0 и AAC

* **H.264** — M6 воспроизводит H.264 High@4.1 в MKV. Main@4.0 —
  более консервативный и распространённый профиль, его понимают все
  аппаратные декодеры.
* **AAC-LC** — заявлен в инструкции; AC3/DTS в MP4 поддерживаются
  гораздо хуже, поэтому звук всегда приводится к AAC. Если исходник уже
  AAC-LC, он копируется.
* **8 бит 4:2:0** — HDR/10-бит и 4:2:2/4:4:4 автомобильные плееры часто
  не читают. Скрипт приводит к `yuv420p`.
* **MP4 + faststart** — `moov` в начале файла, плеер начинает быстрее.
* **Без субтитров по умолчанию** — встроенные субтитры вырезаются,
  внешние не вжигаются, чтобы не ломать совместимость. При необходимости
  используйте `--burn-subs` (требуется libass).

## Советы по флешке

* Папки держите не глубже 2–3 уровней: `M6/Video`, `M6/Music`, `M6/Photo`.
* Не выдёргивайте флешку во время воспроизведения — инструкция M6
  предупреждает, что после этого головное устройство может перестать
  видеть накопители.
* На macOS после копирования на FAT/exFAT появляются служебные файлы
  `._имя`. Они безвредны, но можно убрать их одной командой:

  ```bash
  dot_clean -m /Volumes/USB
  ```

  (или `find /Volumes/USB -name '._*' -delete`).
* Перед извлечением — «Извлечь» в Finder / `diskutil eject`.
* Если M6 вообще не видит флешку: проверьте FAT32/exFAT, MBR-разметку
  и что объём не больше того, что переваривает прошивка. Скрипт не
  форматирует носитель.

## Скорость: почему долго и как ускорить

Перекодирование нескольких фильмов по 1,5–2 часа — это несколько часов видео,
а не копирование. Если запустить 4 задачи одновременно на 8-ядерном Mac
и писать результат на ту же USB-флешку, получается:

* 4 процесса x264 конкурируют за CPU (в старой версии каждый брал
  ~12 потоков — load average подскакивал до ~48 на 8 ядрах);
* 4 файла одновременно читаются с флешки и пишутся на неё же — USB
  становится узким местом;
* в конце каждого файла `+faststart` переписывает весь MP4, чтобы
  `moov` был в начале — на USB это добавляет минуты.

В новой версии по умолчанию 2 задачи, а x264 получает не больше
`ядра / jobs` потоков. Для USB ещё быстрее:

```bash
./m6media.py /Volumes/USB --jobs 2 --x264-preset veryfast
```

Если нужен максимум скорости — пишите результат на локальный диск,
а потом копируйте на флешку:

```bash
./m6media.py /Volumes/USB -o ~/M6 --jobs 2 --x264-preset veryfast
```

Тогда с флешки идёт только чтение, а запись — на быстрый SSD.

## Ограничения

* По умолчанию совместимые файлы **не копируются** в выходную папку —
  они остаются на исходном месте. Это не ошибка; для полной копии
  используйте `--normalize`.
* Защищённые DRM-файлы (Apple Video, Amazon и т. п.) не поддерживаются.
* Повреждённый/недокачанный файл может не читаться — скрипт покажет
  ошибку и продолжит с остальными.
* Берётся **первая** аудиодорожка и **первое** видео; остальные дорожки
  отбрасываются. Внешние `.ac3` рядом с фильмом не подмешиваются. Если
  запустить без `--only video`, эти `.ac3` могут попасть в `Music/` как
  отдельные треки — для фильмов используйте `--only video` или
  `--exclude '*.ac3'`.
* Главы удаляются (`-map_chapters -1`), чтобы не смущать плеер.
* Субтитры: встроенные удаляются; внешние можно вжечь только сборкой
  ffmpeg с libass.
* HDR→SDR без `--tonemap`/zscale будет просто 8-битным, цвета могут быть
  блёклыми. Для SDR-контента это не важно.
* Скрипт не форматирует флешку. Если M6 не видит накопитель, отформатируйте
  его в FAT32 (или exFAT, если он работает) и безопасно извлеките.

## Проверка и отчёты

```bash
# после обработки
python3 m6media.py ~/Movies -o ~/m6-ready --check

# отдельно готовую папку
python3 m6media.py ~/m6-ready --check-only

# посмотреть, что было сделано
python3 -m json.tool ~/m6-ready/_m6media/manifest.json | less
```

`--check` заново читает каждый выходной файл и проверяет:

* контейнер MP4;
* H.264, профиль/level, `yuv420p`, размер, fps;
* AAC-LC, ≤ 2 канала;
* размер < лимита;
* длительность (для неразбитых файлов);
* JPEG и размер фото.

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

Тесты не требуют ffmpeg: проверяются транслитерация, имена, разбор
параметров, эвристика совместимости и планирование разбиения.

## Что проверено

* 38 юнит-тестов (`python3 -m unittest discover -s tests -v`).
* Реальные фрагменты:
  * AVI/XviD + AC3 → MP4/H.264 + AAC (перекодирование);
  * MKV/H.264 + AC3 → MP4 с копированием видео и AAC-звуком;
  * H.264/AAC MP4 → перепаковка без потерь;
  * HEIC/PNG/JPEG → JPEG, в том числе с прозрачностью и без апскейла;
  * поворот телефона (rotation) «запекается» в кадр;
  * разбиение на части под FAT32, включая запись на FAT16/FAT32 и exFAT.
* Полнометражный фильм AVI/XviD (2:01:41):
  исходник AVI/XviD 1,46 ГиБ + AC3 5.1 → MP4 **823 МиБ**,
  H.264 Main@4.0, 720×384, AAC-LC stereo; `--check-only` — OK.
  Перекодирование заняло ~8,5 минуты на Apple Silicon (x264 preset medium).
* Проверка на реальном головном устройстве M6 не выполнялась — это
  следующий шаг; формат собран по инструкции и по проверенным рабочим файлам.

## Наблюдения по M6

* exFAT **работает**, хотя инструкция обещает только FAT16/FAT32.
  Скрипт это учитывает: на exFAT не режет файлы по 4 ГиБ.
* MKV/H.264 + AC3 5.1 **работает**.
* AVI/MPEG-4 Part 2 (XviD/DivX) **не работает** — это и была причина.
* H.264 High@4.1 при 480p работает; для 1080p скрипт перестрахуется и
  сделает Main@4.0.
* Имена с кириллицей и пробелами работают, но по умолчанию скрипт всё
  равно делает ASCII-имена — так надёжнее для разных прошивок.

Если после подготовки какой-то файл всё равно не виден:

* попробуйте `--container mkv` — M6 точно читает MKV с H.264;
* проверьте, что файл лежит не глубже 2–3 папок и имя без `:`/`?`/`*`;
* пришлите вывод диагностики:

```bash
python3 m6media.py "файл" --diagnose
```
